# Execução 2026-10-12 0123

## Resumo
Implementação da spec `044-radar-absorcao-cruzada`, adicionando o painel de "Radar de Absorção Cruzada" ao sistema, que monitora a queda dos preços e picos de volume direcional via `yfinance`.

## Alterações Realizadas
- **Database (`app/database.py`)**: Adicionada estrutura de cache `radar_absorcao_cruzada_cache` e `RadarAbsorcaoCruzadaData`.
- **Collector (`app/collectors/radar_absorcao_cruzada.py`)**: Criado coletor para extrair dados OHLCV intradiários (intervalo 15m, 5 dias) para identificar fundos (quedas \>1.5%) com o dobro da média de volume de queda.
- **Agendador (`app/agendador.py`)**: Programado o coletor para executar periodicamente.
- **Backend (`app/main.py`)**: Expostos os dados da tabela no backend para os templates via variável `radar_absorcao`.
- **UI (`app/templates/index.html`)**: Adicionado um painel do "Radar de Absorção Cruzada" na secão "Alertas Intraday".
- **Testes**: Adicionados os testes unitários correspondentes em `tests/test_radar_absorcao_cruzada.py` em conjunto com a correção das baterias de testes em `test_agendador.py`.
- **Estado/Métricas (`docs/STATE.md` e `CHANGELOG.md`)**: A spec foi marcada como `done`, changelog atualizado e contador de UI avançado para acompanhar a cadência de experiência.

## Decisões Técnicas
- Devido à falta de OHLCV completo no terminal de spark, o endpoint `chart` v8 foi utilizado no collector.
- Para verificar com testes unitários se os valores nulos são ignorados (ausência no cache ou indisponível), o mock garantiu retorno seguro, simulando perfeitamente a queda sem exceções intempestivas no template de loop for.
