# Revisão · spec 194 (Depois de cada faixa no painel geral)

Papel: Revisor, pela última linha do `estado_github` e por `python -m devagent.papel revisor`.

## O que foi feito
- `docs/specs/194-depois-de-cada-faixa-no-painel-geral.md` voltou para `draft`, com `revisada: 2026-11-23` e a seção *Revisão*.
- Motivo: número repetido. `194-pesos-do-ibovespa-numa-tabela-so.md` (#1022) entrou antes com o mesmo `id: 194` e o mesmo `aceite: tests/test_aceite_194.py`. As duas `ready` fariam o desenvolvimento escrever o aceite de uma por cima do da outra, e `exigir_spec_done("194")` e `papel.spec_na_main("194")` não distinguem as duas.
- O conteúdo passou no checklist: o código ainda não faz o que a spec pede, o tamanho é pequeno (`grep -rl "mare-memoria"`: 2 de código, 1 de teste), não há fórmula nova, os aceites são testáveis sem internet e as invariantes são verificáveis no HTML. O Especificador pode reabrir o mesmo texto com o próximo número, só trocando `id` e `aceite`.

## Decisão registrada
Renumerar seria criar número novo, que é do Especificador (regra 8). Entre as duas, sai a que chegou depois na `main` (#1023), pela regra do Revisor para duplicatas (fica a de número menor; aqui, a mais antiga).

## Próximo passo provável
O Revisor revisa `194-pesos-do-ibovespa-numa-tabela-so.md`; o Especificador reabre a do quadro *Depois de cada faixa* com número livre.

## Retrospectiva
- Duas sessões do Especificador reservaram o mesmo número de spec, como já tinha acontecido com o ADR 031 (14/11). Para ADRs, `devagent/tests/test_decisoes.py` passou a reprovar número repetido; para specs não há teste igual. Melhoria proposta: um teste que reprove dois arquivos em `docs/specs/` com o mesmo `id:` (ou o mesmo `aceite:`), para o CI pegar a colisão no segundo PR. Fica para a raia de desenvolvimento (fora da minha raia).
