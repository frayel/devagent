# Relatório de Execução - Correção da Ordem de Fallback do Ibovespa

## Issue Tratada
- **#558**: [verificação] Ordem de fallback errada para Ibovespa
- **Prioridade**: Alta (issue com label `prioridade`, Passo 1)

## Análise
A função `collect_and_save` em `app/collectors/ibovespa.py` estava tentando buscar dados da API da Brapi antes do Yahoo Finance (yfinance) quando o MT5 falhava ou não estava configurado. O critério de aceite da spec 098 especifica claramente que a ordem correta de fontes para o Ibovespa deve ser MT5 -> Yahoo Finance -> Brapi.

## Alterações Realizadas
1. Em `app/collectors/ibovespa.py`:
   - Modifiquei a ordem das condicionais dentro de `collect_and_save()`. Agora, se os dados não forem coletados via MT5, a função tenta `fetch_yfinance()` primeiro e, em seguida, se ainda falhar, tenta `fetch_brapi()`.
2. Em `tests/test_mt5.py`:
   - O teste `test_ibovespa_sem_mt5_segue_para_brapi` foi renomeado para `test_ibovespa_sem_mt5_segue_para_yfinance`.
   - A lógica do teste foi ajustada para verificar se o fallback ocorre corretamente para a função `fetch_yfinance` e não mais para `fetch_brapi`.
3. Em `tests/test_ibovespa.py`:
   - No teste `test_index_route`, adicionei o mock apropriado (respondendo com erro 500) para o endpoint do Yahoo Finance, forçando o comportamento correto de fallback para o Brapi a fim de evitar falhas devido a conexões externas durante a execução dos testes e validar o comportamento do coletor na nova ordem (fallback para o brapi após a falha do yfinance).

## Validação
- Os testes unitários associados ao coletor do Ibovespa e ao fallback foram corrigidos e executados com sucesso usando `pytest`.
- A formatação (ruff) e as tipagens (mypy) foram validadas com sucesso via comando `make verify`.
- Os testes não falham e não exibem warnings indevidos relacionados a chamadas não mockadas.
