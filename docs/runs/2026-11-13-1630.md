## O que foi feito
A #807 acusa um único problema: *Última entrega na main* há mais de 48 h (848e3fc, 09/11). A causa raiz está no repositório e é um impasse do próprio ciclo:

- a página de saúde marca a main parada como **problema**;
- o `auditoria-producao.yml` abre a issue `sistema-com-problema`;
- o `estado_github` (via `fila_specs.instrucao`, ADR 026) manda a sessão corrigir só a issue e **proíbe implementar spec ou abrir outro trabalho**;
- mas a única correção possível para "main parada" é entregar algo na main. Nenhuma sessão podia fazer isso, e a issue não fechava.

Correção:
- `app/services/sistema.py`: `Item` ganha o campo `cura`; `verificar_atividade` declara `cura="entrega"`.
- `devagent/saude.py`: contrato documenta o campo opcional `cura`; nova `pedem_correcao()` exclui problemas com `cura: "entrega"`.
- `devagent/estado_github.py`: quando todos os problemas se curam com entrega, marca a issue de saúde com `cura_por_entrega` e diz para seguir o ciclo.
- `devagent/fila_specs.py`: `_de_producao` ignora issues com `cura_por_entrega`, então a instrução volta a apontar a fila.

O merge deste PR é ele mesmo uma entrega na main, o que limpa o problema da #807.
