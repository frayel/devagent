## Passo executado
Passo 4 - Implementar feature da especificação 029 (Sparklines nos rankings)

## O que foi feito
- Criado novo módulo `app/services/sparkline.py` responsável por calcular os pontos SVG baseados nos 10 últimos fechamentos com um algoritmo genérico (migrado de `mare.py`).
- O serviço `mare.py` foi atualizado para utilizar a nova função comum `build_sparkline`.
- Coletor `highlights.py` para YFinance foi ajustado para pegar uma janela de `15d` pelo endpoint de `spark` e extrair os últimos 10 dias de fechamentos (sem None), passando isso para o schema salvo no banco. O coletor para `brapi` (principal) também foi atualizado para extrair o array via propriedade de histórico `historicalDataPrice` enviando o novo range na requisição (`range=1mo&interval=1d`).
- Coletor `forca_relativa.py` para YFinance atualizado para passar também os últimos 10 dias de fechamentos de `close` no cache `maior_json` e `menor_json`.
- Serviços de `highlights.py` e `forca_relativa.py` modificados para gerar os pontos SVG do sparkline com base nos arrays salvos no banco.
- Templates alterados (adicionada macro de `sparkline` em `componentes.html`).
- Tabelas de Maiores Altas e Maiores Baixas no `index.html` atualizadas para terem a nova coluna `10d` com o componente `sparkline`.
- Alterada a exibição do painel Força Relativa para ser uma tabela, conforme estava desenhado originalmente em KPI, para que os minigráficos fiquem alinhados conforme a spec 029.
- Estilos aplicados no `tema.css` para evitar estouro em responsividade (`min-width` e `max-width`).

## Retrospectiva
- Tive que adaptar o painel de `Força Relativa (30 dias)`, que antes usava a macro `kpi()` com divs, e agora exige uma tabela (já que o objetivo era adicionar nas tabelas de Rankings).
- Falhei na primeira inspeção por esquecer de adaptar a API primária `brapi` a essa nova extração visual. Precisei corrigir pra suportar a requisição de histórico nela também para que a UI mostrasse o sparkline da fonte correta na maioria dos cenários (já que yfinance era apenas fallback).
- Lição de núcleo: Nenhuma.
- Lição do projeto: Ao lidar com dados diários na YFinance em endpoints não-históricos clássicos (como `spark`), precisamos ter um range maior e olhar a propriedade `meta` para pegar o último preço. Além disso, sempre assegurar que a lista tem dados e não possui `None`. Na brapi, deve-se usar `range` e extrair pela chave `historicalDataPrice`.
- Melhoria proposta: Nenhuma.
