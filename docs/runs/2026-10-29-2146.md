## O que foi feito
A página apresentava erros de JavaScript detectados pela auditoria de produção devido ao bloqueio da Content Security Policy (CSP). O bloqueio ocorria pois a diretiva `style-src` exigia `'self'` ou um hash, e a página injetava CSS *inline* através do atributo `style=""` em diversos elementos, como no componente `.heatmap-ativo` (que renderiza os ativos em `app/templates/index.html`) e no script `app/static/ui.js` (que ajustava a largura da `.barra`). Adicionalmente, na página `/sistema`, o CSS estava em uma tag `<style>` inline.

A correção aplicou a política de não utilizar estilos inline:
- Refatorou-se o uso do atributo `style` no template `app/templates/index.html` substituindo o cálculo da cor e opacidade inline por custom properties (CSS variables) através do script `ui.js` preenchendo os estilos de `data-` attributes.
- Alterou-se o arquivo `app/static/ui.js` para atualizar propriedades customizadas (`--barra-w`, `--ativo-peso`, `--ativo-cor` e `--ativo-opacidade`) nas variáveis do elemento ao invés de atualizar o atributo `style.width`.
- Adicionou-se as classes e custom properties correspondentes no arquivo de estilos (`app/static/tema.css`).
- Moveu-se o CSS inline de `app/templates/sistema.html` para o arquivo principal de folha de estilos `app/static/tema.css`.
