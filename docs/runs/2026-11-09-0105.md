## O que foi feito
- **Implementação da Migração (app/consultor/armazenamento.py):**
  - Implementada a função idempotente `migrar_consenso_para_json(conn=None, backend=None) -> int` (com alias `migrar_consenso_legado`).
  - A migração seleciona linhas de `consultor_recomendacoes` onde `consenso` não é nulo/vazio.
  - Ignora registros já em formato JSON válido (`json.loads`).
  - Utiliza `ast.literal_eval` para detectar de forma segura se o valor é um dicionário Python legado em formato `repr` (ex: `"{'compra': 3}"`).
  - Atualiza as linhas correspondentes com o JSON equivalente gerado por `json.dumps(avaliado, ensure_ascii=False)`.
  - Registros de texto simples que não são dicionários avaliáveis (ex: `"cobertura insuficiente"`) permanecem inalterados.
  - Integrada a chamada em `init_db()` do armazenamento do consultor logo após a criação das tabelas e colunas, garantindo que a base seja migrada automaticamente e de forma transparente.
- **Testes de Aceite (tests/test_aceite_132c.py):**

  - `test_migracao_idempotente`: verifica que executar a migração uma segunda vez não altera nenhum registro.
  - `test_leitura_api_consultor_apos_migracao`: valida invariante de que `/api/consultor` continua respondendo e lendo os registros sem erros após a migração.
