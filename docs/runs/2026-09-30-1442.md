## Passo executado
Passo 1 (Issues abertas com label `producao-incorreta`). O painel "Radar de Volume Anormal" estava ausente em produção porque o coletor `volume_alerts.py` retornava `None` quando nenhuma ação preenchia os critérios de volume anormal (mesmo quando a requisição à API externa tinha sucesso). Isso violava o contrato da API `/api/snapshot`, fazendo a chave sumir do JSON.

## O que foi feito
- Modificado o coletor `app/collectors/volume_alerts.py` para retornar um estado de sucesso com uma lista vazia (`alerts_json='[]'`) quando as requisições acontecem normalmente mas não encontram anomalias.
- Modificado o template `app/templates/index.html` para tratar corretamente esse caso, mostrando a mensagem de que não há anomalias, ao invés de exibir o texto de "Dados insuficientes" (reservado para quando o coletor falha).

## Retrospectiva
- Quando os dados estiverem válidos, porém vazios segundo o critério de uma feature, a aplicação deve persistir esse estado "vazio" no cache de banco de dados para garantir que os metadados (como `coletado_em` e `fonte`) permaneçam disponíveis para compor os contratos de API. Retornar `None` deve ser restrito a falhas de comunicação ou erros internos (onde falhamos ao tentar prover os dados).
