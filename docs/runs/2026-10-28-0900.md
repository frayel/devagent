## Retrospectiva
- Tive problemas para testar de forma robusta e idiomática componentes do `asyncio` baseados em requests de thread usando o mock do respx. Devido a limitações do `respx`, não é trivial mockar algo se for jogado noutra thread via `asyncio.to_thread` através do run do pytest no mesmo contexto. Contornei usando uma substituição pontual da função `asyncio.to_thread` pela biblioteca `mock` com uma fake function injetada que invoca diretamente a função-alvo no mesmo escopo local, permitindo que a asserção HTTP aconteça com o contexto respx íntegro. Essa lição serve para qualquer projeto (núcleo) que precise misturar `to_thread`, pytest e HTTP client em side-effects.
